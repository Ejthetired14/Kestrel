Install on your phone

  1. Open this page on the phone and tap Download the APK.
  2. When Chrome warns about this type of file, choose Download anyway.
  3. Open it from the download notification, or from Files → Downloads.
  4. Android will ask to allow installs from this source — allow it for Chrome (or Files), then tap Install.
  5. Open Kestrel. It starts in Demo mode, so no key is needed to try it.

If Play Protect shows a "scan" prompt for an unknown app, tap Install anyway. This is a self-signed sideload build, not a Play Store release.

What works right away

  1. Skills, installed — ⋯ → Skills installs 31 workflows bundled from ponytail and agent-skills. Only their names sit in the prompt; the model reads one with the skill tool when a task matches.
  2. Dictation and spoken replies — a mic in the composer uses the phone’s speech recogniser; Settings can read replies aloud.
  3. Custom instructions — “About you” in Settings rides along with every chat.
  4. Edit, share, drafts — Edit any message to fork the conversation from there, share the whole chat as markdown, and unsent text stays with its chat.
  5. Skills that turn themselves on — a message is scored against the installed skills; when one fits, its full text joins that turn’s instructions and a small chip says which (at most two, never on small talk).
  6. Outline tool — maps a project to its functions, classes and headings with line numbers, so the agent reads only what it needs (the idea from graphify, rebuilt small).
  7. Projects — tap the title bar: create a project (blank, notes, static page, Node script), switch between projects, delete one. Each project is its own folder with its own files and its own sessions.
  8. Import from GitHub — Projects → Import from GitHub: paste a repo URL (or owner/repo, or a /tree/branch link) and it downloads the branch archive into a new project. No git binary needed; no history or submodules.
  9. GitHub commit and push — Settings → GitHub: save a personal access token, create a repository, and commit this project as one commit from the phone. The token stays in the Android keystore and is only ever shown masked.
  10. Open in browser — any file → Open in browser. The app serves the project on 127.0.0.1 and hands the URL to your real browser, so a page's CSS and JS work.
  11. Add files and photos — Files → Add file / Add photo opens the system picker and copies what you choose into uploads/.
  12. Sessions — ☰ lists them; ⋯ gives rename, pin to top, archive/restore, end (read-only, sends blocked) and delete. Project rename keeps its sessions.
  13. Demo model — send a message: streamed reply → tool call → permission dialog → file written → diff in Changes. Completely offline.
  14. No key at all — Pollinations, Kilo Code, LLM7.io and OVHcloud AI answer anonymously, including tool calls; rate limited. Nothing to sign up for.
  15. Every free tier from awesome-free-llm-apis — Aion Labs, Cohere, Z AI, Gonka, ModelScope, NVIDIA NIM, SiliconFlow and Cloudflare Workers AI ship with their free model ids; pick the provider, add its key, done.
  16. Free models with a free key — Settings → Load free models lists today's zero-cost OpenRouter models (15 right now). An OpenRouter account with no payment is enough.
  17. Your own gateway — Provider → Custom / gateway: point it at a self-hosted OmniRoute (http://192.168.x.x:20128/v1, model auto), an OpenCode Zen token endpoint, or LM Studio on a laptop. No key in the app if the gateway has none.
  18. DeepSeek — built-in provider with deepseek-chat and deepseek-reasoner.
  19. Skills — Settings → Add skill from URL installs a markdown instruction pack (ponytail, agent-skills, …) into the workspace; it is added to the model's instructions every turn.
  20. Self-check — ⋯ → Run self-check runs 24 engine checks on the phone and lists pass/fail per step.
  21. Other models — paste an OpenAI, OpenRouter, Groq or Gemini key in Settings (or a custom OpenAI-compatible base URL). Keys are encrypted with the Android keystore.

Tools: read · write · edit · ls · glob · grep · delete · todo · web fetch. No shell on the phone build.

Built from the same project as the desktop app. Nothing is uploaded anywhere except the model provider you choose.
